# AGENTS.md — правила работы с проектом

Правила для ИИ-агента (DSH, Claude Code, Codex и других инструментов), который правит этот репозиторий.
Состояние работ, числа калибровки и список оставшихся задач — в [`docs/STATE.md`](docs/STATE.md). Прочитайте его перед первой правкой.

## Что это за проект

Нативный плагин для AutoCAD (AutoLISP + Visual LISP + ActiveX/COM + DCL + CUIX): строит стрелки отклонений между точками разных циклов измерений (геомониторинг, шпунт). Среда: **полный AutoCAD 2018 и новее (не LT)**, Windows. Чертёж — в метрах, длины подписываются в миллиметрах.

## Готовый сценарий «стрелки → ведомость → Excel»

В DSH есть скилл **`lcm-arrows-report`**: полный цикл — отрисовать стрелки `lcm:geo-run`, построить ведомость `LCMDEV`, выгрузить ячейки и заполнить второй блок в «Уч. 6 шпунт.xlsx» (`tools/lcm_table_to_xlsx.py`). На просьбы «отрисуй стрелки», «построй ведомость», «заполни таблицу отклонений» загружайте этот скилл, а не собирайте шаги заново. Он же содержит список грабель: длинные LISP в `SendCommand`, `T` как имя переменной, допуск примыкания 0.1. Рабочая копия — в `~/.dsh/skills`, версия для git — [`SKILLS/lcm-arrows-report/SKILL.md`](SKILLS/lcm-arrows-report/SKILL.md): при правке скилла обновляйте обе.

## Контекст прошлой сессии — читать в начале работы

Если в каталоге есть `docs/LAST_SESSION.md`, прочитайте его в первом ходе новой сессии: это автоснимок последних 10 реплик предыдущей сессии (на чём остановились, что обсуждали).

Обновить снимок вручную:

```bash
node tools/last_session.cjs              # записать docs/LAST_SESSION.md
node tools/last_session.cjs --stdout     # только показать, не писать
node tools/last_session.cjs --limit 20   # больше реплик
```

Если команда напечатала `FALLBACK <путь>` — песочница не дала писать в каталог проекта: прочитайте файл по этому пути и запишите его содержимое в `docs/LAST_SESSION.md` своим инструментом записи. Файл локальный, в git не попадает. Осмысленные итоги (решения, числа калибровки, что осталось) по-прежнему идут в `docs/STATE.md`, а не сюда.

## Кодировки — самое важное

| Файлы | Кодировка |
|---|---|
| `lcm_ui.lsp`, `lcm_ui.dcl`, `lcm_diag.lsp`, `lcm_geo.lsp`, `lcm_chain.lsp`, `lcm_check.lsp`, `lcm_table.lsp` | **Windows-1251** |
| `lcm_main.lsp`, `lcm_data.lsp`, `lcm_core.lsp`, `lcm_config.lsp` | UTF-8 (кириллицы в них нет) |
| `README.md`, `docs/*.md`, `AGENTS.md`, `tools/*.py` | UTF-8 |

- AutoCAD читает `.lsp` и `.dcl` как ANSI: если файл из первой строки таблицы сохранить в UTF-8, русские строки в интерфейсе превратятся в кракозябры.
- Переводы строк во всех исходниках — **CRLF**.
- Правьте файлы в 1251 инструментом, который умеет писать в этой кодировке; обычный UTF-8-редактор их испортит.

## Проверки перед загрузкой в AutoCAD

AutoCAD для них не нужен:

```bash
python tools/lisp_check.py lcm_*.lsp    # баланс скобок и строк
python tools/ref_check.py               # вызовы несуществующих функций
```

Обе должны проходить чисто. Затем в AutoCAD: `LCMRELOAD` и проверка нужной команды.

## Правила

1. Не переписывать без нужды код, уже подтверждённый в AutoCAD на реальном чертеже (этапы 0–3). Косметические переделки — только по явной просьбе.
2. Работать в ветке; `main` держать в рабочем состоянии.
3. Не коммитить локальные данные: `reports/`, `settings/*.cfg`, `settings/lcm_aliases_*.csv`, `*.dwg`, `*.err` — они уже в `.gitignore`.
4. Не менять молча поведение по умолчанию: `LCMAUTO` — только отчёт (ничего не рисует), `LCMAUTODRAW` — рисует. Спорные пары не рисуются никогда, только попадают в отчёт.
5. Радиус поиска пар «по координатам» — по умолчанию 5 единиц чертежа (поле «Порог по координатам»). В цепочке циклов порог считается как `0.5 ×` пятого процентиля расстояний до соседей и вручную не подкручивается (обоснование — в `docs/STATE.md`).
6. Новые тексты для пользователя (сообщения, подписи в DCL) — по-русски и в кодировке файла.

## Git: коммиты и отправка на GitHub

В ограниченном режиме песочницы запись в `.git` и сеть недоступны: `git add/commit/push/fetch` падают с `Permission denied` на `.git/index.lock` или со `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`. Это **не** повод перекладывать коммит и пуш на пользователя.

- Для `git commit`, `git push`, `git fetch`, `git clone` и любых сетевых команд сразу запрашивайте **разовое** расширение доступа на конкретную команду (в DSH это `sandbox_permissions: danger-full-access` плюс пояснение) и выполняйте её сами. Постоянный полный доступ для этого не требуется — пользователь подтверждает одну команду.
- В пояснении к запросу пишите, что именно произойдёт: какая команда, какая ветка, уходит ли что-то на GitHub, будет ли перезапись истории.
- Перезапись истории — только по явному согласию пользователя и только через `--force-with-lease`; перед этим проверьте, что ветку не тянули в других копиях.
- Перед коммитом смотрите `git status` и `git diff --cached --name-only`: `git add -A` легко захватывает скриншоты, черновики и тестовые чертежи.
- После пуша проверяйте, что `HEAD` и `origin/main` совпадают, и сообщайте хеш коммита.

## Автоматизация AutoCAD (мост для агента)

`tools/cad_bridge.ps1` подключается к **запущенному** AutoCAD 2018 через COM и даёт агенту канал к живому чертежу. AutoCAD сам не запускает: если процесс `acad.exe` не найден — сообщает об этом.

| Глагол | Что делает |
|---|---|
| `status` | AutoCAD, открытый DWG, загружен ли LCM, версия |
| `eval "<lisp>"` | выполнить выражение, вернуть результат или текст ошибки |
| `load <файл>` | загрузить `.lsp/.fas/.vlx` в текущий чертёж |
| `dump [-Layer X] [-Out f]` | объекты ModelSpace: тип, слой, handle, координаты, текст |
| `layers` | таблица слоёв |
| `shot -Out f.png` | снимок окна AutoCAD |
| `cmd "<команда>"` | отправить произвольную команду |
| `undo mark\|back` | маркер и откат |
| `cuix <файл>` | загрузить меню (для кнопок) |
| `report -Kind chain\|geo\|check` | разобрать свежий отчёт LCM (AutoCAD не нужен) |

Правила работы через мост:

1. По умолчанию — только чтение и отчёты. Отрисовка (`cmd`, вызовы с рисованием) — лишь после явного согласия пользователя.
2. Перед изменениями — `undo mark`; при ошибке — `undo back`.
3. Не вызывать интерактивные команды `LCM`, `LCMCHAIN`, `LCMGEOFILL`: они ждут ввода и подвесят мост. Звать только функции — `(lcm:geo-run ...)`, `(lcm:chain-run ...)`.
4. После отрисовки — `LCMCHECK` и сверка числа пар с отчётом.
5. Таймаут вызова (`-TimeoutSec`, по умолчанию 30 с) означает зависание на диалоге, а не повод повторять вслепую.
6. `cad_bridge.ps1` сохранять **в UTF-8 с BOM**: Windows PowerShell 5.1 без BOM читает файл как ANSI и ломает кириллицу.

## Команды проекта

| Команда | Назначение |
|---|---|
| `LCM` | диалог: слои, параметры стрелок, авто-сопоставление, «по координатам» |
| `LCMSTATS`, `LCMDUMP`, `LCMDIAGPAIR` | диагностика: статистика по слою, выгрузка точек, сравнение двух слоёв |
| `LCMGEOFILL` | сопоставление пары слоёв по координатам в радиусе (по умолчанию 5) |
| `LCMCHAIN` / `LCMAUTO` / `LCMAUTODRAW` | цепочка циклов: с вопросами / по настройкам с отчётом / с отрисовкой |
| `LCMCHECK` | проверка отрисованного: длины стрелок и пересечения пар |
| `LCMDEV` | ведомость отклонений: таблица пар точек двух слоёв в чертеже (`lcm_table.lsp`, слой `LCM_ВЕДОМОСТЬ`) |
| `LCMRELOAD` | перезагрузка модулей после правок |
