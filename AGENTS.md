# AGENTS.md — правила работы с проектом

Правила для ИИ-агента (DSH, Claude Code, Codex и других инструментов), который правит этот репозиторий.
Состояние работ и калибровка — [`docs/STATE.md`](docs/STATE.md); принятые решения и их обоснования — [`docs/research/INDEX.md`](docs/research/INDEX.md). Прочитайте оба перед первой правкой.

## Что это за проект

Нативный плагин для AutoCAD (AutoLISP + Visual LISP + ActiveX/COM + DCL + CUIX): строит стрелки отклонений между точками разных циклов измерений (геомониторинг, шпунт). Среда: **полный AutoCAD 2018 и новее (не LT)**, Windows. Чертёж — в метрах, длины подписываются в миллиметрах.

## Готовый сценарий «стрелки → ведомость → Excel»

В DSH есть скилл **`lcm-arrows-report`** — полный цикл: `lcm:geo-run` → `LCMDEV` → заполнение второго блока «Уч. 6 шпунт.xlsx». На просьбы «отрисуй стрелки», «построй ведомость», «заполни таблицу отклонений» загружайте его, а не собирайте шаги заново. Рабочая копия — в `~/.dsh/skills`, версия для git — [`SKILLS/lcm-arrows-report/SKILL.md`](SKILLS/lcm-arrows-report/SKILL.md): правя скилл, обновляйте обе.

## Контекст прошлой сессии

Если есть `docs/LAST_SESSION.md` — прочитайте в первом ходе новой сессии: это снимок последних 10 реплик предыдущей. Обновить: `node tools/last_session.cjs` (файл локальный, в git не попадает). Осмысленные итоги всё равно идут в `docs/STATE.md`.

## Память проекта: поиск по корпусу

`tools/memory_index.py` — FTS5-индекс по `*.md`, `*.lsp`, `*.dcl`, `*.py`, `*.ps1`, `*.cjs`, `reports/*.csv` и истории git. База — в `.memory/` (в `.gitignore`), настройки — `memory.json`. История поломок и детали — [`docs/research/01-memory-index.md`](docs/research/01-memory-index.md).

```bash
py -3 tools/memory_index.py status | build | update
py -3 tools/memory_index.py search "запрос" [--kind md] [--limit 3]
py -3 tools/memory_index.py show README.md --at "7.10" --section
```

1. На вопрос «где / когда / почему / что решили» — сначала `search`, а не чтение README или `STATE.md` целиком.
2. Найдя файл, не читайте его целиком: `show <путь> --at "<подстрока>"` печатает нужный раздел (для LISP/CSV — окно ±15 строк).
3. `search` сам догоняет изменения; `--no-update` отключает, `--any` ослабляет до ИЛИ, `--raw` — синтаксис FTS5.
4. Кодировки определяются по содержимому (UTF-8 / BOM / cp1251): обычный grep по cp1251-кириллице **не находит**.
5. Индекс производный — коммитить нечего. Если `db_dir` смотрит наружу, `search` откроет базу только для чтения и предупредит.

## Кодировки — самое важное

| Файлы | Кодировка |
|---|---|
| `lcm_ui.lsp`, `lcm_ui.dcl`, `lcm_diag.lsp`, `lcm_geo.lsp`, `lcm_chain.lsp`, `lcm_check.lsp`, `lcm_table.lsp` | **Windows-1251** |
| `lcm_main.lsp`, `lcm_data.lsp`, `lcm_core.lsp`, `lcm_config.lsp` | UTF-8 (кириллицы в них нет) |
| `README.md`, `docs/*.md`, `AGENTS.md`, `tools/*.py`, `memory.json` | UTF-8 |

- AutoCAD читает `.lsp` и `.dcl` как ANSI: UTF-8 превратит русские строки в кракозябры.
- Переводы строк во всех исходниках — **CRLF**. Правьте 1251-файлы инструментом, который умеет эту кодировку.

## Проверки перед загрузкой в AutoCAD

```bash
py -3 tools/lisp_check.py lcm_*.lsp    # баланс скобок и строк
py -3 tools/ref_check.py               # вызовы несуществующих функций
py -3 tools/memory_check.py            # память: размер AGENTS.md, полнота research/
```

Все три должны проходить чисто. Затем в AutoCAD: `LCMRELOAD` и проверка нужной команды.

## Правила

1. Не переписывать код, подтверждённый в AutoCAD на реальном чертеже (этапы 0–3). Косметика — только по явной просьбе.
2. Работать в ветке; `main` держать в рабочем состоянии.
3. Не коммитить локальное: `reports/`, `settings/*.cfg`, `settings/lcm_aliases_*.csv`, `*.dwg`, `*.err`, `.memory/` — они в `.gitignore`.
4. Не менять молча поведение по умолчанию: `LCMAUTO` — только отчёт, `LCMAUTODRAW` — рисует; спорные пары не рисуются никогда.
5. Радиус пар «по координатам» — 5 единиц чертежа (поле «Порог по координатам»); в цепочке циклов порог `0.5 × p05` вручную не подкручивать.
6. Новые тексты для пользователя — по-русски и в кодировке файла.
7. **Один шаг — один вызов.** Каждый шаг оплачивается всем контекстом (~100 тыс. токенов), поэтому число шагов дороже объёма прочитанного: независимые чтения собирайте в одну команду, ориентир — 2–3 вызова на вопрос о коде. `AGENTS.md` править не больше одного раза за задачу: правка вклеивает файл в контекст целиком.
8. Файлы памяти (`AGENTS.md`, `docs/STATE.md`, `docs/research/*`, `SKILLS/*`) — это **инструкции, которые агент исполняет**, то есть код: их правки ревьюятся, а не «просто заметки». Репозиторий публичный.
9. Крупное решение или разбор оформляется файлом `docs/research/NN-тема.md` (вопрос / решение / детали / следствия) + строка в [`INDEX.md`](docs/research/INDEX.md) и в [`docs/LOG.md`](docs/LOG.md); в `STATE.md` — короткая ссылка, не абзац.
10. `AGENTS.md` держать в пределах 12 КБ — проверяет `tools/memory_check.py`. Проектную конкретику выносить в `docs/`, здесь только правила.

## Git: коммиты и отправка на GitHub

- `git add` и `git commit` в песочнице работают. Сети нет: `git push`/`fetch`/`clone` падают со `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`.
- Для сетевых команд сразу запрашивайте **разовое** расширение доступа (`danger-full-access`) и выполняйте их сами — перекладывать на пользователя не нужно.
- В пояснении пишите: какая команда, какая ветка, уходит ли что-то на GitHub, будет ли перезапись истории. Перезапись — только с согласия и через `--force-with-lease`.
- Перед коммитом смотрите `git status` и `git diff --cached --name-only`: `git add -A` ловит скриншоты и черновики.
- После пуша проверьте, что `HEAD` и `origin/main` совпадают, и сообщите хеш.

## Автоматизация AutoCAD (мост)

`tools/cad_bridge.ps1` подключается к **запущенному** AutoCAD 2018 через COM. Сам AutoCAD не запускает.

| Глагол | Что делает |
|---|---|
| `status` | AutoCAD, открытый DWG, загружен ли LCM, версия |
| `eval "<lisp>"` | выполнить выражение, вернуть результат или текст ошибки |
| `load <файл>` | загрузить `.lsp/.fas/.vlx` в текущий чертёж |
| `dump [-Layer X] [-Out f]` | объекты ModelSpace: тип, слой, handle, координаты, текст |
| `layers` / `shot -Out f.png` | таблица слоёв / снимок окна AutoCAD |
| `cmd "<команда>"` / `undo mark|back` | произвольная команда / маркер и откат |
| `cuix <файл>` | загрузить меню (для кнопок) |
| `report -Kind chain|geo|check` | разобрать свежий отчёт LCM (AutoCAD не нужен) |

1. По умолчанию — только чтение и отчёты; отрисовка — после явного согласия пользователя.
2. Перед изменениями — `undo mark`; при ошибке — `undo back`.
3. Не звать интерактивные `LCM`, `LCMCHAIN`, `LCMGEOFILL` — они ждут ввода и подвесят мост; звать функции `(lcm:geo-run …)`, `(lcm:chain-run …)`.
4. Таймаут вызова — признак зависания на диалоге, а не повод повторять вслепую. `cad_bridge.ps1` хранить в UTF-8 с BOM: PowerShell 5.1 без BOM ломает кириллицу.

## Команды проекта

| Команда | Назначение |
|---|---|
| `LCM` | диалог: слои, параметры стрелок, авто-сопоставление, «по координатам» |
| `LCMSTATS`, `LCMDUMP`, `LCMDIAGPAIR` | диагностика: статистика по слою, выгрузка точек, сравнение двух слоёв |
| `LCMGEOFILL` | сопоставление пары слоёв по координатам (радиус 5) |
| `LCMCHAIN` / `LCMAUTO` / `LCMAUTODRAW` | цепочка циклов: с вопросами / отчёт / отрисовка |
| `LCMCHECK` | проверка отрисованного: длины и пересечения пар |
| `LCMDEV` | ведомость отклонений таблицей (слой `LCM_ВЕДОМОСТЬ`) |
| `LCMRELOAD` | перезагрузка модулей после правок |
