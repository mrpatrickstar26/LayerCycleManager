Одна строка на событие, формат: `## [ГГГГ-ММ-ДД] тип | суть`. Типы: `run` (прогон на объекте, проверка в AutoCAD), `decision` (принятое решение), `incident` (поломка и её причина), `lint` (ревизия памяти).

Зачем: `docs/research/` хранит тематические решения без хронологии, а git знает только про код. Здесь — то, чего нет ни там, ни там: прогоны, приёмка, инциденты.

Смотреть последние события: `grep "^## \[" docs/LOG.md | tail -5` (или `py -3 tools/memory_index.py search "logs"`).

## [2026-11-10] decision | Excel дописывает блоки вплотную справа
`tools/lcm_table_to_xlsx.py` больше не пишет в фиксированный `E:H` и не очищает его: находит первый свободный участок из 4 столбцов (`A:D` → `E:H` → `I:L` → …), номер цикла берёт на 1 больше последнего блока, формула `D` считает по своим столбцам. Проверено на копии книги двумя прогонами.

`core.autocrlf=true` скрывает расхождение: в индексе LF, в рабочей копии LF, для git изменений нет. Лечение — `git checkout --`, политика закреплена в `.gitattributes` (`* text=auto eol=crlf`). Там же исправлена метка пропуска в `--fast`, хук включён.
