## 1. Что это за проект

Нативная программа для AutoCAD (AutoLISP + Visual LISP + ActiveX/COM + DCL + CUIX) для геодезии и геомониторинга: строит стрелки отклонений между одноимёнными или сопоставленными точками разных циклов измерений (например, шпунт котлована).

Требования к среде: **полный AutoCAD 2018 или новее (не LT)**, Windows. Чертёж — в метрах, длины подписываются в миллиметрах.

## 2. Что сделано в этой итерации (этапы 0–3)

| Этап | Модуль | Команды | Суть |
|---|---|---|---|
| 0. Диагностика | `lcm_diag.lsp` | `LCMSTATS`, `LCMDUMP`, `LCMDIAGPAIR` | чтение точек и подписей, статистика по слою, выгрузка в CSV, сравнение двух слоёв |
| 1. Сопоставление по координатам | `lcm_geo.lsp` | `LCMGEOFILL` | закрывает пробелы авто-сопоставления: находит пары с разными именами по близости координат; в диалоге `LCM` добавлены поле «Порог по координатам» и кнопка «Дополнить по координатам» |
| 2. Цепочка по циклам | `lcm_chain.lsp` | `LCMCHAIN`, `LCMAUTO`, `LCMAUTODRAW` | протягивает идентичность точек по всей серии циклов через таблицу идентичности; устойчиво к пропускам циклов и длинным сериям |
| 3. Проверки | `lcm_check.lsp` | `LCMCHECK` | сверяет нарисованные длины с расчётными, ищет пересечения истинных отрезков отклонений, пишет отчёт |

Дополнительно в этой итерации: из программы **удалено удаление стрелок** (из диалога убраны «Слой удаления:», «Стрелок:», кнопка «Удалить»; из кода — `lcm:delete-arrows`, `lcm:delete-by-handle`; ключ настроек `DEL_LAYER`). Поиск стрелок `lcm:find-arrows` сохранён — он нужен модулю проверок.

Все изменения проверены в AutoCAD на реальном чертеже (test2.dwg) и подтверждены пользователем.

## 3. Принятые правила сопоставления (и почему именно такие)

1. **Режим «по координатам»** (кнопка в диалоге, команда `LCMGEOFILL`, функция `lcm:geo-run`). Простое правило: для каждой точки слоя A берётся ближайшая точка слоя B **в радиусе** (по умолчанию **5** единиц чертежа). Если на одну точку B претендуют несколько точек A, побеждает пара с меньшим расстоянием. Уже найденные пары (по именам, вручную) не трогаются, их точки исключаются из поиска. Спорных пар в этом режиме нет.
   Плата за простоту: точка, у которой настоящей пары нет, но в радиусе оказалась чужая, получит «лишнюю» пару. На данных «Уч.4» при радиусе 5 так появилась пара `48` → `s2` (4.72 м); при радиусе 4 она исчезает, а все настоящие (до 1.24 м) остаются.
2. **Имена — сильнее координат** (диалог, «Авто-сопоставление»). Точное совпадение уникальных имён принимается сразу, но с проверкой расстояния: если точки дальше `2 × радиуса`, пара **не** принимается. Причина: в цикле 52 нашлась ложная пара `44` ↔ `44` на 14.4 м — разные физические точки с одинаковым именем.
3. **Цепочка циклов** (`LCMCHAIN`, `LCMAUTO`, `LCMAUTODRAW`) — строгий вариант: взаимно ближайший кандидат, порог `0.5 ×` пятого процентиля расстояний до соседей и ограничение «второй кандидат не ближе `1.5 ×`». Пятый процентиль, а не минимум, — из-за двух точек `46.2` в 0.01 м в цикле 52. Спорные пары не рисуются, а попадают в отчёт.
4. **Дубликаты имён исключаются** из автоматического сопоставления (иначе `lcm:add-or-replace-point` молча теряет точку).

### Текущие значения по умолчанию

- радиус поиска пар «по координатам» — **5** единиц чертежа (`lcm:geo-default-radius`);
- радиус поиска подписи точки (её имени) — **8** единиц (`lcm:text-search-radius`, хранится в `settings/lcm_settings.cfg`).

### Откалиброванные значения (строгое правило цепочки, данные «Уч.4»)

| Слой | Расстояние до соседа (p05) | Порог для пары |
|---|---|---|
| Уч.4 Цикл 0 | 4.873 м | — |
| Уч.4 Цикл 50 | 3.718 м | 0↔50 → **1.86 м** |
| Уч.4 Цикл 51 | 3.716 м | 0↔51 → **1.86 м** |
| Уч.4 Цикл 52 | 3.259 м | 0↔52 → **1.63 м** |

Фактические отклонения среди пар по именам: 0↔50 — максимум **1.262 м** (тот самый «1250 мм»), 0↔51 — 0.461 м. Минимальное расстояние между соседними точками ~3 м, накопленное за 56 циклов — до 1.25 м.

### Эталонные пары (подтверждены пользователем)

- **0 ↔ 52 — 16 пар.** По именам: 38, 39, 40, 41, 42, 46, 47, 49, 50, 51, 52. Переименованные (добраны по координатам): `37*`→`36.1` (0.218 м), `38*`→`36.3` (0.187 м), `45`→`46.1` (0.118 м), `43`→`44` (0.251 м), `44`→`45.1` (1.241 м).
- **0 ↔ 51 — 21 пара.** Дополнительно: `43`→`t3` (0.244 м) и `44`→`t44` (1.241 м).
- Точки `s1`…`s4`, `I1`, `I9` пары имеют в другом слое — их отсутствие в списке нормально.
- Регрессия по этому эталону: совпадение 16/16, лишних пар нет, ложная пара `44`↔`44` корректно уходит в спорные.

## 5. Правила работы с кодом (важно для агента)

1. **Кодировки.** `lcm_main.lsp`, `lcm_data.lsp`, `lcm_core.lsp`, `lcm_config.lsp` — UTF-8 (ASCII без кириллицы). `lcm_ui.lsp`, `lcm_ui.dcl`, `lcm_diag.lsp`, `lcm_geo.lsp`, `lcm_chain.lsp`, `lcm_check.lsp` — **Windows-1251** (AutoCAD читает .lsp как ANSI, русский текст иначе превращается в кракозябры). Переводы строк — CRLF во всех файлах.
2. **Перед загрузкой в AutoCAD** прогонять статические проверки (AutoCAD не нужен):
   ```
   python tools/lisp_check.py lcm_*.lsp      # баланс скобок и строк
   python tools/ref_check.py                 # вызовы несуществующих функций
   ```
3. **Не менять уже проверенный в AutoCAD код ради косметики** — правки делать только по делу и с последующей проверкой в AutoCAD.
4. **Работать в ветке**, `main` держать в рабочем состоянии.
5. Правки интерфейса (`lcm_ui.lsp`, `lcm_ui.dcl`) требуют записи файлов в Windows-1251 — обычный текстовый редактор с UTF-8 их испортит.

## 6. Как запускать (кратко)

| Задача | Команда |
|---|---|
| Диалог, ручное и авто-сопоставление, отрисовка | `LCM` |
| Статистика по слою | `LCMSTATS` |
| Выгрузка точек слоя в CSV | `LCMDUMP` |
| Сравнение двух слоёв (имена + кандидаты по координатам) | `LCMDIAGPAIR` |
| Сопоставить по именам и координатам для пары слоёв | `LCMGEOFILL` |
| Пройти цепочку циклов (с вопросами) | `LCMCHAIN` |
| Цепочка по сохранённым настройкам, только отчёт | `LCMAUTO` |
| То же с отрисовкой стрелок | `LCMAUTODRAW` |
| Проверить отрисовку (длины и пересечения) | `LCMCHECK` |

Типовой цикл работы: `LCMAUTO` (посмотреть отчёт `reports/lcm_chain_*.csv`) → если всё верно, `LCMAUTODRAW` → `LCMCHECK`.

Для агента (без диалога) есть функции:
```lisp
(lcm:geo-run   "Уч.4 Цикл 0" "Уч.4 Цикл 52" nil nil)   ; отчёт
(lcm:geo-run   "Уч.4 Цикл 0" "Уч.4 Цикл 52" nil T)     ; отчёт + отрисовка
(lcm:chain-run '("Уч.4 Цикл 0" "Уч.4 Цикл 50" "Уч.4 Цикл 51" "Уч.4 Цикл 52") nil)
```

## 7. Что осталось / известно

- **1.2.0:** правило «по координатам» упрощено — ближайшая точка в радиусе (по умолчанию 5 единиц чертежа); кнопка в диалоге переименована в «по координатам»; попутно убраны лишние проверки из этого режима.
- **Устранено в 1.1.0:** удалены три неиспользуемые функции (`lcm:chain-in-list`, `lcm:geo-dup-names`, `lcm:geo-min-spacing`); версия синхронизирована — `1.1.0` в `lcm:version`, README и этом файле.
- **Возможные доработки** (по желанию пользователя): кнопка цепочки циклов в диалоге `LCM`; интерактивный разбор спорных пар (зум на пару); отчёт по цепочке в диалоге; CHECK-проверка внутри отрисовки как обязательный шаг.
- **Проверено на двух объектах:** «Уч.4» (серия циклов 0→50→51→52) и «Уч.6» (11 пар, циклы 0→1). На чертежах с другой плотностью точек сначала запускать `LCMSTATS` и смотреть `p05`: от него зависит порог строгого правила в цепочке циклов.
- **Модуль `lcm_table.lsp` (команда `LCMDEV`) — ведомость отклонений, 30.10.2026.** Первая утилита, написанная агентом и проверенная в живом AutoCAD: `(lcm:dev-table "Уч 6 Цикл 0" "Уч 6 Цикл 1" 5.0)` → нативная таблица `AcDbTable` на слое `LCM_ВЕДОМОСТЬ`, вставка справа от габаритов точек, все марки нулевого цикла, у марки без пары — прочерк. Откат — `undo back`.
- **`LCMDEV` переоформлен по образцу Excel «Уч. 6 шпунт.xlsx» (30.10.2026):** столбцы `№ марки | ΣΔX | ΣΔY | D`, заголовок «Смещение по x и y (мм)» отдельной строкой, подпись цикла `Цикл 1 ДД.ММ.ГГГГ`, высота текста 5, строки и столбцы компактнее. Попутно выяснено: (1) в Windows-1251 нет `Σ`/`Δ` — в ячейки они передаются escape-кодами `\U+03A3`/`\U+0394`; (2) первая строка `AddTable` — штатный заголовок, текст в объединённой ячейке этой строки не выводится, поэтому заголовок ставится в неё без объединения; (3) объединять ячейки нужно до заполнения текстом; (4) в DIESEL месяц — `MO`, а не `MM`; (5) у `AcDbTable` нет `SetRowType`, зато есть `SetCellAlignment`, `SetRowHeight`, `SetColumnWidth`, `MergeCells`.
- **Правки моста после сбоя (30.10.2026):** резервная ветка `New-Object -ComObject AutoCAD.Application` запускала второй экземпляр AutoCAD с пустым «Чертеж1.dwg», после чего COM-регистрация указывала на уже закрытое приложение. Теперь автозапуск убран, добавлены повторы при `RPC_E_CALL_REJECTED`, а перед снимком свёрнутое окно разворачивается (иначе PrintWindow снимал иконку 160×28).

### Канал автоматизации для ИИ-агента (этапы 0–1 пройдены)

- `accoreconsole` (headless-ядро AutoCAD 2018) **не подходит**: LISP выполняется, но `(vlax-get-acad-object)` возвращает `nil` — ActiveX недоступен, а LCM построен на `vla-*`. Проверено 29.10.2026.
- Рабочий канал — COM в запущенный AutoCAD (`tools/cad_bridge.ps1`, 10 глаголов). Этап 0: код и парсер отчётов сверены с эталоном — 16 пар по «Уч.4» 0↔52, 11 пар по «Уч.6» 0↔1, длины 16/16.
- **Этап 1 (29.10.2026, «Уч.6 тест.dwg», AutoCAD 2018):** проверены `status`, `load` (LCM 1.2.0), `eval` (с перехватом ошибок LISP), `dump` (реальные координаты), `layers`, `shot`, `undo mark/back`, `report`. Вызов `(lcm:chain-run '("Уч 6 Цикл 0" "Уч 6 Цикл 1") nil)` вернул `(2 11 11 0 0 0 0 …)` и отчёт с **11 парами** — совпадает с эталоном. В модели 431 объект.
- **Ограничение «зрения»:** PNG-скриншот сохраняется (`shot`), но текущая модель DSH не принимает изображения; для визуальной проверки нужна модель с поддержкой картинок, иначе опираемся на `dump`.
- **Подводные камни, исправленные в мосте:** `AcDbPoint` не отдаёт координаты через ActiveX `Coordinates` — читать через `entget`/assoc 10; `TryParse` в русской локали не понимает точку как десятичный разделитель (нужна инвариантная культура); `lcm:loaded` в статусе путался с версией; `tblnext` вместо `vla-get-frozen`.
- Ограничение: `SendCommand` асинхронен, результат забирается файлом; длинные LISP-пейлоады (>2 КБ) могут упереться в буфер командной строки — при необходимости переносить код в `.lsp` и грузить `load`.

## 8. Если работа продолжается на другом компьютере

1. Скопировать репозиторий (`git clone` или копия папки целиком).
2. При необходимости перенести локальные данные: `reports/`, `settings/lcm_aliases_*.csv`, `settings/lcm_settings.cfg`, `test2.dwg` — они не в Git.
3. В AutoCAD добавить папку программы в **Support File Search Path** (или грузить `lcm_main.lsp` через `APPLOAD`).
4. В новой сессии с агентом сказать: «Прочитай `docs/STATE.md` и `README.md`, продолжай».
5. Проверить работоспособность без AutoCAD: `python tools/lisp_check.py lcm_*.lsp` и `python tools/ref_check.py`.
