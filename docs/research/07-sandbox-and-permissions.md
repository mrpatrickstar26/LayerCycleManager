# 07. Песочница DSH, права NTFS и запись в проект

**Статус:** принято 05.11.2026

**Вопрос:** почему процессы песочницы (`python`, `git`) не могли писать в папку проекта, хотя режим был `workspace-write`, и что с этим делать.

**Решение:** папке проекта выставлена метка целостности Low (`icacls <папка> /setintegritylevel "(OI)(CI)L" /T`). Содержимое, владелец и права доступа не менялись. При пересоздании папки метку нужно поставить заново.

## Детали

- Процессы DSH в песочнице работают на **низком уровне целостности** (Low IL, `S-1-16-4096`), а объекты папки были Medium. Windows по умолчанию запрещает запись «снизу вверх», и это ограничение не выдаётся никаким правом доступа: проверка идёт по мандатной метке, а не по списку доступа.
- Симптом: корень рабочей папки писался, а `LayerCycleManager` — нет. Корень был помечен при регистрации workspace, вложенная папка появилась раньше и осталась Medium.
- Диагностический скилл `diagnose-windows-sandbox-acl` вернул `NOT_THIS_CLASS`: список доступа в порядке (оба нужных разрешения на месте, посторонних записей нет). Отчёт — в `.acl-recovery/` рядом с рабочей папкой.
- Удаление подкаталогов ограничено штатным deny-правилом `Everyone → DeleteSubdirectoriesAndFiles`. Удаление файлов при этом работает. Это не поломка.
- PowerShell здесь — Windows PowerShell 5.1: `Add-Content` без `-Encoding` пишет в системной ANSI-кодировке (cp1251) и портит UTF-8-файлы. Текст писать через `[IO.File]::WriteAllText(..., New-Object System.Text.UTF8Encoding($false))` или инструментом агента.

## Следствия

- `py -3 tools/memory_index.py build|update`, `git add`, `git commit` идут без расширения доступа.
- Сеть по-прежнему закрыта: `git push`/`fetch`/`clone` падают со `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS` — нужен разовый `danger-full-access`.
- Запись вне рабочей папки (профиль, `~/.dsh`, база вне проекта) — тоже только с разовым расширением.
