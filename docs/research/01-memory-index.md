# 01. Индекс памяти проекта (FTS5)

**Статус:** принято 05.11.2026

**Вопрос:** Как агенту искать по корпусу, если обычный grep по cp1251-модулям не находит кириллицу.

**Решение:** Локальный полнотекстовый индекс `tools/memory_index.py` на stdlib `sqlite3`; база в `.memory/` внутри проекта, настройки в `memory.json`.

## Детали

- **Память проекта — FTS5-индекс (05.11.2026).** `tools/memory_index.py`: полнотекстовый поиск по `*.md`, `*.lsp`, `*.dcl`, `*.py`, `*.ps1`, `*.cjs`, `reports/*.csv` и истории git. Зависимостей нет (stdlib `sqlite3`), база вне репозитория: `%LOCALAPPDATA%\cache\lcm-memory\`. Команды `build` / `update` / `search` / `status`; `search` сам догоняет изменения, при пустом результате ослабляет AND до ИЛИ, нормализует ё/е, кодировки определяет по содержимому (UTF-8 / BOM / cp1251). Замер: 170 документов, база ~1 МБ, запрос 150–180 мс. Причина появления: обычный grep по cp1251-модулям кириллицу **не находит** (проверено: «допуск» в `lcm_table.lsp` → 0 совпадений). Протокол работы — в `AGENTS.md`, раздел «Память проекта».
- **Индекс починен: работает в ограниченной песочнице (05.11.2026).** Было две поломки: `python` в PATH — заглушка Microsoft Store, а `build`/`update` падали с `unable to open FTS5: unable to open database file`, потому что база лежит в `%LOCALAPPDATA%\cache\lcm-memory\` (вне рабочей папки, а workspace-write туда не пишет). Что сделано в `tools/memory_index.py`: (1) `search` и `status` при отказе в записи сами открывают базу в режиме `mode=ro`, при необходимости `immutable=1`, и печатают предупреждение «индекс не обновлён, выдача может быть неполной» — поиск теперь работает **без всякого расширения доступа**; (2) у `build`/`update` вместо сырой ошибки SQLite понятное объяснение с двумя путями (разовое расширение доступа либо `LCM_MEMORY_DIR` на доступный каталог, `%TEMP%` тоже годится); (3) каталог базы переопределяется `LCM_MEMORY_DIR`; (4) `status` показывает `readonly`, дату обновления в читаемом виде; (5) вывод принудительно UTF-8 — в русской Windows Python писал cp1251 в терминал, ожидающий UTF-8, и кириллица шла мусором; тот же вывод добавлен в `tools/lisp_check.py` и `tools/ref_check.py`, а `lisp_check.py` теперь сам разворачивает шаблон `lcm_*.lsp` (PowerShell, в отличие от bash, шаблоны не раскрывает и передаёт строку как есть). Замер после правки: `status` → 171 документ, 1,16 МБ, `readonly: true`; `search "радиус по координатам"` → 3 попадания за ~0,2 с. Важно: обычные процессы (`python`, `git`) не пишут и **внутрь** рабочей папки — файлы правит только инструмент агента.
- **Индекс: `show` — выдача куска файла вместо чтения целиком (05.11.2026).** Причина: агент, найдя файл поиском, читал его целиком (README.md — 54 тыс. символов ради раздела на 2,5 тыс.). Добавлено в `tools/memory_index.py`: (1) `show <путь> --at "<подстрока>"` — печатает markdown-раздел, в котором встретилась подстрока (от заголовка до следующего заголовка того же или верхнего уровня), для LISP/CSV без заголовков — окно ±15 строк (`--context`), `--section` ищет только среди заголовков, `--lines 40:80` — диапазон, `--max` — предел строк; (2) в выдаче `search` теперь есть `путь:строка` и `[раздел]`; (3) `--raw` — запрос передаётся в синтаксисе FTS5 (OR, NOT, NEAR), подсмотрено в исходном проекте ObsidianDataWeave. Замер: `show README.md --at "7.10" --section` → 2,5 тыс. символов вместо 54 тыс.
- **Индекс переехал в проект, песочница больше не мешает (05.11.2026).** База теперь в `.memory/` в корне репозитория (каталог в `.gitignore`), `memory.json` → `db_dir: ".memory"`. В `tools/memory_index.py` относительный `db_dir` считается от корня проекта, а не от текущего каталога — иначе запуск из другого места уводил базу в чужой каталог. Заодно нашлась причина, почему песочница не пускала `python`/`git` писать в папку проекта: процессы DSH идут на низком уровне целостности (Low IL), а объекты папки были Medium — Windows запрещает запись «вверх». Корень рабочей папки был помечен правильно, поэтому там запись работала, а `LayerCycleManager` — нет. Лечение: `icacls "<папка>" /setintegritylevel "(OI)(CI)L" /T` (659 объектов; содержимое, владелец и права доступа не менялись). Проверено: `build`/`update` и `git commit` идут без расширения доступа, `git push` по-прежнему требует разового `danger-full-access` — у песочницы нет доступа к сетевым учётным данным (`schannel: SEC_E_NO_CREDENTIALS`).
- **Индекс стал переносимым: `memory.json` (05.11.2026).** `PATTERNS` и `SKIP_DIRS` были зашиты в код, поэтому скрипт нельзя было переиспользовать в другом проекте. Теперь настройки лежат в `memory.json` в корне (`patterns`, `skip_dirs`, `git_history`, `db_dir`), поверх значений по умолчанию; путь переопределяется `LCM_MEMORY_CONFIG`. Добавлена команда `init` (пишет конфиг по умолчанию, `--force` — перезапись), `status` показывает путь к конфигу и число шаблонов. В песочнице DSH `init` не пишет файл (обычные процессы не пишут в рабочую папку) — конфиг создаётся инструментом агента или вне песочницы.
