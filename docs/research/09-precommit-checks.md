# 09. Проверки перед коммитом: check_all.py, git-хук и политика CRLF

**Статус:** принято 08.11.2026, дополнено 09.11.2026

**Вопрос:** как не выпустить в `main` файл с испорченной кодировкой, LF вместо CRLF или битой ссылкой, если проверки запускаются вручную и про них забывают.

**Решение:** `tools/check_all.py` — одна команда на все проверки с кодом возврата 1; её же вызывает git-хук `tools/hooks/pre-commit`, включаемый через `--install-hook`; политика переводов строк закреплена в `.gitattributes`, чтобы не зависеть от `core.autocrlf` конкретной машины.

## Детали

- Порядок проверок в `check_all.py`: кодировки и переводы строк по содержимому файла; остатки маркеров конфликта `<<<<<<<` / `>>>>>>>`; дубли команд `C:` среди `.lsp` и `.dcl` (сейчас 15 команд); валидность `memory.json` и наличие ключей `patterns`, `skip_dirs`, `git_history`, `db_dir`; затем `lisp_check.py`, `ref_check.py`, `memory_check.py --deep`.
- Файлы берутся из индекса git (`git ls-files --cached`), а не обходом диска: новый файл проверяется сразу после `git add`, неотслеживаемый мусор не мешает. Если git недоступен, скрипт откатывается на обход дерева.
- Правила кодировок в коде совпадают с `AGENTS.md`: `.lsp` и `.dcl` — Windows-1251, `.ps1` — UTF-8 с BOM, `.md/.txt/.json/.py/.cjs/.csv/.gitignore` — UTF-8 без BOM, `tools/hooks/*` — LF, остальное — CRLF. Проверка cp1251 идёт от обратного: файл с байтами ≥ 0x80, который при этом валиден как UTF-8, — это пересохранённый `.lsp`, и AutoCAD покажет кракозябры.
- `--fast` пропускает `memory_check --deep`; в сводке строка помечается «пропущено (--fast)», чтобы пропуск нельзя было принять за успешную глубокую проверку. `--full` печатает вывод подпроверок целиком.
- Хук — тонкая обёртка на `sh`, ищет интерпретатор каскадом `LCM_PYTHON` → `py -3` → `python3` → `python`. Если ничего не нашлось, коммит не пропускается молча: хук выходит с кодом 1 и подсказывает переменную. Включение — локальная настройка клона (`core.hooksPath=tools/hooks`), с репозиторием не приезжает.
- `.gitattributes`: `* text=auto eol=crlf` плюс `tools/hooks/* text eol=lf`. Второе правило обязательно: при `core.autocrlf=true` хук приезжает с CRLF, и `sh` падает на `\r: not found`. Первое закрывает другую дыру: в индексе всё хранится как LF, поэтому клон с `autocrlf=false` получал LF в рабочей копии и валил проверку на первом же запуске.
- Границы: ловится «файл цел и не сломан». Правильность геометрии и чисел так не проверить — только прогон в AutoCAD.

## Следствия

- В песочнице DSH `sh` не стартует, поэтому коммит из-под агента идёт с `git commit --no-verify`, а `check_all.py` запускается вручную перед коммитом. Хук страхует обычный терминал, не агента.
- `--fast` — для цикла правок; перед коммитом в `main` гонять полный прогон.
- Проверка переводов строк смотрит байты рабочей копии, а `git status` при `autocrlf=true` такого расхождения не показывает: файл с LF в копии и LF в индексе для git «не изменён». Так и нашлись семь файлов, записанных инструментами с одиночным LF (`SKILLS/lcm-arrows-report/SKILL.md`, `memory.json`, `tools/cad_bridge.ps1`, `tools/last_session.cjs`, `tools/lcm_table_to_xlsx.py`, `tools/lisp_check.py`, `tools/ref_check.py`): `git status` чист, а `check_all` падал. Лечение — `git checkout -- <файлы>`, то есть перечитать их из индекса.

## Условия пересмотра

- Если проверка кодировок начнёт ложно срабатывать на бинарных файлах без расширения — дополнить `BINARY_SUFFIXES`.
- Если хук понадобится и в песочнице — заменить `sh`-обёртку на прямой вызов Python и проверить, стартует ли он из-под git в DSH.
